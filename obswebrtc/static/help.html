Quick start

Phones and tablets stream their camera straight to OBS over your local network. Each phone takes a camera slot (Cam 1–5), and each slot shows up in OBS as a Browser Source.

  1. Connect the phone to the same network as this PC (Wi-Fi or USB-C Ethernet adapter).
  2. Open the sender page: press Show phone QR code above and scan it with the phone's camera. The first time, the phone warns about the certificate; accept it (how).
  3. Pick a camera slot on the phone, press Start and allow camera (and microphone) access.
  4. In OBS, add a Browser Source with that slot's URL from the table below, size 1920×1080.

Using the phone sender

ControlWhat it does
Camera slotWhich OBS camera this phone becomes. "(in use)" means another phone has it; starting on that slot takes it over and the other phone stops.
LensBack camera by default. You can switch while live without dropping the stream.
BitrateVideo quality cap; can be changed while live. Guide: wired 8–12 Mbps, 5 GHz Wi-Fi 4–8 Mbps, busy Wi-Fi 2.5–4 Mbps. "Auto" lets the browser decide, which is often lower than you want for recording.
AudioSends the phone's microphone with the video. Phone call processing (echo cancel, noise suppression, auto gain) is off so ambience sounds natural. Set it before Start.
DimBlacks out the screen while streaming continues. Tap anywhere to wake.
Don't press the power button or switch apps while live. Browsers stop the camera when the page goes to the background. The page keeps the screen awake on its own; use Dim instead. If it does get locked, the stream reconnects by itself a few seconds after you unlock.
  • Keep the phone on a charger for long sessions (the screen stays on).
  • To prevent accidental taps or app switches: App pinning (Android) or Guided Access (iPhone/iPad).
  • The phone remembers its slot, lens, bitrate and audio choice for next time.

URL options

Add these to the end of a camera URL:

  • &quiet: hide the "Waiting for Cam N" text, so it never ends up in a recording.
  • &stats: show connection stats and delay. For setup only; it is visible in the picture.
  • &delay=150: override the stable buffer for this camera only (milliseconds).

Script settings

OBS → Tools → Scripts → obs_webrtc.py

  • OBS port (8080): local address the Browser Sources use.
  • Allow phones / Phone port (8443): the HTTPS address phones use.
  • Max cameras (5): how many slots phones can choose. Changing ports or max cameras restarts the server, and phones reconnect by themselves.
  • Stable buffer (100 ms): see audio sync. Changes apply live.

Audio sync

Each phone's own audio and video stay in sync automatically. What needs adjusting is other audio, like a microphone plugged into the PC: it arrives before the phone video, which takes roughly 150–300 ms to reach OBS.

The stable buffer (now 100 ms) holds every camera at the same steady delay, so a single offset stays correct.

  1. Add &stats to one camera URL and check the video buffer stays near the target.
  2. Clap test: clap in front of the phone, close to your mic, and record a few seconds.
  3. In the recording, count the frames between your hands meeting (video) and the clap spike (mic). At 30 fps one frame is about 33 ms.
  4. In OBS, open Edit → Advanced Audio Properties and set the mic's Sync Offset to that delay.
  5. Remove &stats again.

If you change the stable buffer, adjust the Sync Offset by the same amount.

Recording each camera for editing

Use the Source Record plugin to save every camera to its own file, alongside the main recording.

  1. Right-click the camera's Browser Source → Filters → add Source Record.
  2. Record mode: Recording, so all cameras start and stop with the main recording.
  3. Format: MOV or MP4. DaVinci Resolve doesn't handle MKV well; if you record MKV, remux it first (File → Remux Recordings).
  4. Encoder: H.264 or HEVC at high quality (e.g. CQP 18–20).
Each Source Record filter is one hardware encoder session, plus one or two for your stream and recording. Check how many sessions your GPU allows before adding more cameras.

In Resolve, select the camera clips and your main audio, then right-click → Auto Sync Audio → Based on Waveform.

Network

  • All phones and this PC must be on the same network, behind the same router. A guest Wi-Fi usually blocks devices from reaching each other, so don't use it.
  • USB-C Ethernet adapters: turn Wi-Fi off on those phones so they're sure to use the cable.
  • Wi-Fi phones: use 5 GHz and stay near the access point.
  • Windows Firewall: when asked, allow OBS (obs64.exe) on Private networks. If you missed the prompt, phones will hang on "Connecting…" (see troubleshooting).

Certificate

Phones only allow camera access on HTTPS pages, so this PC uses a self-signed certificate. Each phone shows a warning the first time; it's safe to accept it for this address.

  • Chrome (Android): Advanced → Proceed to … (unsafe)
  • Safari (iPhone/iPad): Show Details → visit this website → Visit Website
  • Firefox: Advanced → Accept the Risk and Continue
Get rid of the warning (optional)

Create a certificate the phones trust with mkcert:

  1. On this PC: mkcert -install
  2. In the obs-webrtc folder: mkcert -cert-file certs/lan.pem -key-file certs/lan-key.pem localhost
  3. Install mkcert's root certificate (mkcert -CAROOT shows where) on each phone.
  4. Reload the script in OBS. certs/lan.pem is used automatically when present.

Using your own trusted certificate (certs/lan.pem). Phones shouldn't show a warning.

Troubleshooting

Phone says "Camera access needs HTTPS"

The page was opened with http://. Use the https:// address from the QR code.

Phone can't open the page, or stays on "Connecting…"
  • Check the phone is on the same network (not guest Wi-Fi or mobile data).
  • Allow OBS through Windows Firewall: Windows Security → Firewall → Allow an app → OBS Studio → Private.
  • Try another address in the QR code selector; the PC may have several network adapters.
  • iPhone/iPad: open the address again and re-accept the certificate warning.
Phone is live but OBS shows "Waiting for Cam N"

Check the slot number on the phone matches the URL's cam= number. Then right-click the Browser Source → Properties → Refresh cache of current page.

Phone says "waiting for OBS"

No Browser Source is showing that slot right now. Add one, or turn off "Shutdown source when not visible" so it stays connected outside the current scene.

Picture froze after the phone locked or switched apps

Unlock the phone and return to the browser; it reconnects within a few seconds. If not, press Stop and Start.

No sound from a camera

Tick Audio on the phone before pressing Start, and turn on Control audio via OBS in the Browser Source. The camera then appears in the audio mixer.

Phone says "Another device took Cam N"

Two phones picked the same slot; the newest one wins. Choose a free slot on one of them.

Picture is blurry or blocky

Raise the bitrate on the phone. If it gets worse when you do, the network can't keep up: move closer to the access point, switch to 5 GHz, or use a USB-C Ethernet adapter. &stats shows packet loss.

Scan with the phone

First visit: accept the certificate warning on the phone.

Doesn't load? Try another address; this PC has more than one network adapter.

Phone access is off, or no network address was found. Turn on Allow phones in the script settings.
